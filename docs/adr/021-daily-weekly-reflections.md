# ADR-021: 振り返りの本文は LLM を使わずに組み立て、音声と小テストは押したときだけ生成してキャッシュする

## Status

Accepted（2026-11-01。実装は #807、レイアウトは #808・#809）

## Context

その日の学習を振り返るには、ノート・フィードバック・学習メモを 1 つずつ探しに行く必要があり、手間がかかるため振り返られていなかった。開くだけでその日（その週）の学習がまとまっていて、当日中に振り返れる場所が要る。

一方で、振り返らない日もある。開くたび・毎日自動で LLM を呼ぶと、使われない生成に費用がかかる。LLM の 1 日の上限（ADR-018）の考え方にも合わせる必要がある。

## Decision

1. **本文は LLM を使わない**: 期間内に終えたセッションを集め（`repositories/reflection_repository.py`）、既存のノートの要約・フィードバックのうまく説明できなかった所・学習メモの疑問と回答から、種類 × ノート（学習メモ）の単位に組み立てる（`services/reflection.py`）
   - 日は `REVIEW_TIMEZONE` の暦日。learning・review は `ended_at`、explore は `study_memos.created_at` で数える。trial・synthesis・失敗したもの・ノートが消えたものは入れない
2. **音声の原稿と小テスト（4 択 3〜5 問）は、ボタンを押したときに初めて LLM で作る**（`services/reflection_generation.py`・`graph/prompts/reflection.py`）
3. **生成したものは `reflection_generations` にキャッシュする**: 本文の内容と言い回し（「今日」か「M月D日」か）のハッシュが同じならキャッシュを返し、変わったときだけ作り直す。その日に学習を足すと、次に押したときに作り直される
4. **上限**: 原稿と小テストは `llm_usages` の `reflection_script`・`reflection_quiz` として、LLM を呼ぶ前に予約する（1 日 20 回。`DAILY_REFLECTION_GENERATION_LIMIT`）。キャッシュを返せたときは数えない。読み上げは `speech_usages` にセッションなしで数える
5. **未読**: 日ごとに最後に開いた時刻を `reflection_views` に記録し、その後に終えたセッションがある日を未読として日付のレールに点を出す

## Reasons

- **本文を LLM に書かせない**: 中身は既存のノートとフィードバックにすでにある。LLM で書き直すと、開くたびに費用と待ち時間がかかり、元のノートと食い違う要約が混ざりうる。組み立てるだけなら、すぐに開けて、元と一致する
- **押したときだけ生成する**: 音声と小テストは、振り返る日にしか要らない。毎日の自動生成は、使われない日の分が無駄になる
- **内容のハッシュでキャッシュする**: 同じ日を何度開いても、同じ内容なら待たずに再生でき、費用もかからない。日時ではなく内容で比べるので、学習を足した日だけ作り直される
- **キャッシュのときは数えない**: 上限は LLM の費用を抑えるためのもの（ADR-018）なので、LLM を呼ばなかった操作は数えない

## Consequences

- 本文はノートとフィードバックの質にそのまま左右される。ノートの要約が弱いと、振り返りも弱い
- 期間をまたいで内容を統合したり、ノート同士の関係を説明したりはしない。それが要るなら、まとめノート（`synthesis`）で扱う
- キャッシュはプロンプトの版をハッシュに含めないので、プロンプトを変えても、内容が変わるまでは古い原稿・小テストが返る
- 下タブバーの項目が 6 つになった
