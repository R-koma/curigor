# ADR-011: 声で話すとき、聞き取り（目的・教材・今の理解）を選択肢のカードではなく声で聞く

## Status

Accepted（2026-10-06）。ADR-008 の「選択肢を声で選ばせない」判断は残し、聞き取りの聞き方だけを変える

## Context

学習の開始時は、目的・教材・今の理解をクリックの選択肢のカード（`IntakeCardView`）で聞いている。声で話す対話（ADR-010）の最中でも、カードはそのまま出る。読み上げるのは冒頭の一文（`intake_lead`）だけで、3 つの問いは読まれない。声で始めても、答えるにはカードを見てクリックする必要があり、入口だけマウス操作が要る。

## Decision

**声で話しているときは、聞き取りカードの代わりに 3 つの問いを文字で並べ、冒頭の一文に続けて問いを一度に読み上げる。ユーザーはまとめて話して答える。**

- 選択肢は出さない。問いの文面から、クリック用の注記（「（複数選択可）」）を除く（`lib/intake.ts` の `intakeQuestionText`）
- 読み上げる文面は「冒頭の一文 + 各問い + 『まとめて話して、終わったら「以上」と言ってください。』」（`intakeSpeechText`）。`useChatWebSocket` が speechBus に流す文面と、▶ で読み直す文面を同じ関数で作る
- 問いの表示に切り替える条件は、声の対話中（`status !== "off"`）か、声の回答を入力欄で確認している間（`restoredTranscript` あり）。回答が入力欄に入ると声の対話は止まる（`holdForReview`）が、確認中にカードへ戻ると表示が入れ替わるため
- 回答は従来どおり、「以上」で入力欄に入れて確認してから手動で送る
- 「すべてスキップして始める」は残す
- 声で話していないときは、従来のカードのまま

## Reasons

- **一度に聞く**: 話した回答は、既存の自由文の返信として `extract_intake` が 3 項目をまとめて抽出する。サーバー・`LearningState`・eval・capture を変えずに済む。1 問ずつ 3 往復に分けると、聞き取りの完了判定と state が変わる
- **自動送信しない**: カードへの回答（カード直後の自由文を含む）は取り消せない仕様のまま。送った後に誤認識を直せないので、送る前に入力欄で確認させる（ADR-010 の `holdForReview` と同じ理由）
- **聞き直さない**: 抜けた項目は、学習開始の声かけが「未回答」として扱い、触れない。聞き直しはサーバーの変更を要するので、今は入れない

## Consequences

- 変更はクライアントだけ（`VoiceIntakePrompt`・`intakeSpeechText`・学習画面の切り替え）。`GRAPH_VERSION` は上げない
- 読み上げる文面が `intake_question` の `content` と別になる。▶ の保持（`(speechKey, 文の番号)`）がずれないよう、聞き取りのメッセージは常に `intakeSpeechText` を読む
- 声で話していない状態で届いた問いは自動では読まれない。後から声で話し始めると問いの表示に替わるので、▶ で読む
- 話した回答の抽出漏れ（3 項目のうち一部が空になる）は、`input_mode = 'voice'` の聞き取りへの回答と、そのセッションの `learning_goal` / `learning_source` / `prior_knowledge` で見る。多ければ、抜けた項目だけ聞き直す変更を検討する
