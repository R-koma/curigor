# ADR-017: エラーに機械が読めるコードを持たせ、WebSocket の版を接続時に確かめる。REST の URL に版は付けない

## Status

Accepted（2026-10-17。実装は #600）

## Context

REST のエラーは FastAPI 既定の `{"detail": ...}` で、`detail` は文字列のときと（検証エラーの）配列のときがあった。WebSocket の `error` も日本語の文だけで、クライアントは文言でしか区別できなかった。

クライアント（Vercel）とサーバー（Railway）は別々にデプロイする。開いたままのタブは古いクライアントのまま、新しいサーバーにつなぎ直す（デプロイで WebSocket が切れると自動で再接続する）。メッセージの形を変えると、そのタブは壊れたまま動き続ける。`/api/` にも WebSocket のメッセージにも版が無かった。

## Decision

1. **エラーの形**: REST は `{"code": "...", "detail": "..."}` に揃える。`code` は `server/api/errors.py` の `ErrorCode`（列挙）。ルートは `ApiError(status, ErrorCode.X, "...")` を投げる。素の `HTTPException`（FastAPI・Starlette が投げる 404・405 など）は状態コードから `code` を決め、`detail` は文字列にする。検証エラーは `code: "validation_error"` と文字列の `detail` に、項目ごとの内容を `errors` で添える。未捕捉の例外は `internal_error`
2. **WebSocket のエラー**: `error` に `code` を必須で持たせる（`schemas/websocket_message.py` の `WsErrorCode`）。`detail` は画面に出す日本語の文のまま
3. **WebSocket の版**: クライアントは最初の `authenticate` に `protocol_version` を載せる。サーバーは `PROTOCOL_VERSION` と比べ、違う（載っていないも含む）ときは `code: "protocol_version_mismatch"` の `error` を返す。接続は閉じずに開いたままにし、以後に届いたメッセージのたびに同じ `error` を返す。セッションには触れない
4. **版が合わないときの画面**: クライアントは入力中の文を `sessionStorage` に残して、自動でページを読み直す。読み直した後のセッションの開始・再開の知らせで、残した文を入力欄に戻す。1 分以内にもう一度合わなければ読み直さず、`detail` を表示する
5. **REST の URL に版は付けない**（`/api/v1` にしない）。互換性を壊す変更は、WebSocket の版を上げて開いているタブに読み直させる

## Reasons

- **`code` を足す理由**: 文言を直すとクライアントの分岐が壊れる。`detail` の型が揺れると、クライアントは中身を読めない
- **版を `authenticate` に載せる理由**: サーバーは `authenticate` を生の JSON として読み、知らないキーを無視する。新しいクライアントが古いサーバーにつないでも壊れない
- **サーバーで比べる理由**: 古いクライアントは版を比べる処理を持たない。サーバーが日本語の `detail` で再読み込みを促せば、古いタブにも伝わる
- **閉じない理由**: 閉じると古いクライアントは切断として自動の再接続を繰り返し、`detail` の代わりに「接続が切れました」を表示する
- **自動で読み直す理由**（R-koma の決定）: 版が合わない状態で続けられることは無い。入力中の文は保存して戻すので、読み直しで失うものは無い
- **1 分の間隔を置く理由**: サーバーが先にデプロイされ、Vercel のデプロイが終わるまでは、読み直しても同じ古いクライアントが返る。間隔を置かないと読み直しを繰り返す
- **`/api/v1` を付けない理由**（R-koma の決定）: クライアントとサーバーは同じ人が一緒にデプロイし、外部の利用者もいない。URL の版を並べて保つ必要が無く、移す手間だけがかかる

## Consequences

- REST のルートでエラーを返すときは `ApiError` と `ErrorCode` を使う。新しい理由のエラーには `ErrorCode` に値を足す
- WebSocket の `error` を送るときは `code` を付ける。新しい理由には `WsErrorCode` に値を足す
- **WebSocket のメッセージの形を互換性の無い形に変えたら、`PROTOCOL_VERSION` をサーバー（`server/schemas/websocket_message.py`）とクライアント（`client/lib/protocol.ts`）の両方で上げる**。上げたリリースでは、開いていたタブがすべて 1 回読み直す。足すだけの変更（任意のキー・新しいメッセージの種類で古いクライアントが無視できるもの）では上げない
- この変更を入れたリリースで、開いていたタブ（版を送らない古いクライアント）は 1 回読み直しを促される
- REST に互換性の無い変更を入れるときは、クライアントを先に、または同時にデプロイする。URL の版で古いクライアントを守ることはしない
- 外部に API を公開する、または別のクライアント（モバイルアプリなど）を持つときは、URL の版を見直す
