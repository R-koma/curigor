# ADR-008: 音声モードでは自動送信と読み上げを入れ、聞き取りカードの表示中だけ自動送信しない

## Status

Accepted（2026-10-03。実装は #378）

## Context

ADR-007 のフェーズ1（#41）は、音声入力を「録音 → 文字起こし → 入力欄で確認・修正 → 送信」で入れ、D4 として自動送信しないと決めた。学習対象の専門用語は誤認識されやすく、誤認識をそのまま送ると事前分析と `covered_aspects` に誤りが入り込むためである。

#378 は、学習・復習を最初の入力から応答まで声で進める**音声モード**を、#41 の音声入力とは別のモードとして足す。入力だけ音声で応答が文字のままでは、声で使う体験として成り立たない。ADR-007 の段階表のフェーズ2（読み上げ）にあたり、D4 をこのモードに限って見直す。

利用場面はまず机（画面を見ながら）とし、ハンズフリーは後で広げられる構造にしておく。

導入前の基準値として、#41 の音声発言のうち、ユーザーが送信前に文字起こしを直した割合と差分の大きさを次のクエリで取る。結果は #378 の PR に記録する。

```sql
SELECT
  COUNT(*) AS voice_messages,
  COUNT(*) FILTER (WHERE content <> raw_transcript) AS edited,
  ROUND(AVG(ABS(LENGTH(content) - LENGTH(raw_transcript)))::numeric, 1) AS avg_length_diff
FROM dialogue_messages
WHERE role = 'user' AND input_mode = 'voice' AND raw_transcript IS NOT NULL;
```

## Decision

**音声モードに限り、録音を止めたら文字起こしをそのまま送る。聞き取りカードの表示中は自動送信せず、入力欄に入れて確認させる。**

- 録音の開始は常にユーザー操作（マイクを押す）。読み上げの後に自動で録音しない。無音検出による自動停止と、読み上げ中の割り込みはフェーズ3として入れない
- 応答の読み上げはサーバー経由の REST（`POST /api/speech`、`gpt-4o-mini-tts`）。クライアントが応答のストリームを文に切り、順に要求して先読みしながら再生する
- 自動送信した発言は `dialogue_messages.input_mode = 'voice_auto'` で区別する
- 誤認識は、送信後に既存の鉛筆ボタン（直前の発言の取り消し）で入力欄へ戻して直す。戻した発言は元の文字起こしを保ち、直して送ると `raw_transcript` が残る

## Reasons

- **聞き取りカードでは自動送信しない**: カードへの回答は取り消せない仕様のため、送信後に直せない。送信前に確認できる必要がある。選択肢を声で選ばせる方法（LLM での対応づけ、番号の読み上げ）は、画面を見られる机の利用では利点が薄いわりに実装が増えるので採らない。自由に話した回答は、既存の自由文の返信（`extract_intake`）としてサーバー変更なしで処理できる
- **録音の開始は常にユーザー操作**: プロテジェ効果ではユーザーが考えてから長く説明するので、読み上げ後に自動で録音すると、考えている間の無音にも文字起こしの費用がかかり、300 秒の上限も消費する。無音検出とセットで扱うべきで、フェーズ3に回す
- **文単位で読み上げる**: 応答の全文を待つと、事前分析・全文生成・音声合成の遅延が積み上がる。文ごとに要求し、再生中に次の文を先読みすれば、最初の文が出た時点で読み始められる。サーバーは「文を受けて音声を返す」だけで、WebSocket・グラフ・state に触れない
- **サーバー経由の API**: ADR-007 で Web Speech API を採らなかった理由（品質・ブラウザ差・使用量の制御）がそのまま当てはまる。文字起こしと同じ構成（使用量の記録・1 日の上限・Langfuse の trace）にでき、費用を実測できる
- **自動送信を `voice_auto` で区別する**: 取り消した発言は DB から消えるので、印が無いと確認を挟まない発言の誤認識の影響を測れない

## Consequences

- グラフ・`LearningState`・eval・capture は変えない。`GRAPH_VERSION` も上げない。音声合成はプロンプトに影響しない
- `dialogue_messages.input_mode` の CHECK に `voice_auto` を足し、`user_message` と `start_learning` に任意の `auto_sent`（真なら `raw_transcript` 必須）を足した
- 自動送信の誤認識の影響は、`voice_auto` の発言の `raw_transcript` と、取り消して直した後の `content` の差で見積もる。導入前の基準値（Context のクエリ）と比べる
- 読み上げの使用量は `speech_usages`（文字数）に記録し、`DAILY_SPEECH_CHAR_LIMIT` を `REVIEW_TIMEZONE` の暦日で数える。判定はアトミックではない。Langfuse には `synthesize-speech`（generation）として、対話セッションの session に紐づけて送る
- ブラウザは自動再生を制限するので、モードの切り替え・マイク・送信のユーザー操作の中で `AudioContext` を解錠する。解錠前の読み上げは何もしない
- 応答の途中でマイクを押す・発言を取り消すと読み上げは止まり、同じ応答の残りは読まない。何も流れていないときに止めても、次の応答は読む
- 読み上げの 1 日上限に達しても本文は画面に残るので、学習は続けられる
- ハンズフリー（読み上げ後の自動録音・無音検出・割り込み）を足す場合は `useVoiceMode` に閉じて足せる。その判断はこの ADR を見直す
