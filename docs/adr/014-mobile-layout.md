# ADR-014: スマホ幅のレイアウトは CSS で切り替え、入力手段の違いだけコードで判定する

## Status

Accepted（2026-10-09）

## Context

主な利用端末は PC で、サイドバーはホバーで開き、幅はマウスで変え、ナビバーはセッションの操作を横一列に詰めていた。画面の高さは `100vh` で、モバイル Safari ではアドレスバーの分だけ入力欄が画面の外に出る。スマホのブラウザで学習・復習の対話（音声を含む）とノートの閲覧を最後まで行えるようにしたい。ネイティブアプリ・PWA は対象外。

## Decision

**見た目の出し分けは Tailwind の variant だけで行い、CSS で書けない振る舞いだけ React のフック（`useCoarsePointer()`）で分岐する。**

- 幅の軸は `md:`（768px）。何を置くか・並べ方・余白・列数・見出しの大きさを決める
- 入力手段の軸は `pointer-coarse:` / `pointer-fine:`。押せる領域（44px）・Enter の意味・キーボードショートカットの案内を決める。CSS で書けないものは `hooks/use-coarse-pointer.ts` が `matchMedia("(pointer: coarse)")` を購読する（サーバーでは `false`）
- スマホ幅では `Sidebar` と `Navbar` を隠し、`MobileHeader`（区切り線の無い 1 行。メニューのボタンとページの見出し）と `MobileTabBar`（復習・新規・履歴・まとめ）を出す。メニューのボタンで開く左のドロワー（`components/ui/sheet.tsx`）は、上にロゴ、真ん中にカレンダー（押すと全画面）・続きから・最近のノート、下にアカウントを置く
- 見出しの文言は `lib/nav-links.ts` の `PAGE_TITLES` に持つ。ページの `h1` はスマホ幅で `max-md:sr-only`（読み上げには残す）、ヘッダーの行の見出しは `aria-hidden`
- セッション中（`NavbarSlotContext` の `navbarCenter` が non-null）はタブバーを隠し、ヘッダーをセッションの内容に置き換える。別の state は持たない
- 画面の高さは `h-dvh`。`viewport` は `viewportFit: "cover"` にし、下端の部品に `env(safe-area-inset-bottom)` を足す
- 「声で話す」は全画面の音声モードを作らず、今のパネルをタッチ向けに整える

## Reasons

- **JS で幅を判定してレイアウトごと切り替えない**: サーバーは幅を知らないので、初回は PC のレイアウトを描いてからスマホへ切り替わり、画面が跳ねる。CSS なら最初から正しい形で描ける
- **幅ではなく入力手段で振る舞いを決める**: タブレットに外付けキーボードを付けた端末では、幅が狭くても Enter で送りたい。逆に大きなタッチ画面では幅が広くても 44px が要る
- **セッション中の判定をスロットの有無で決める**: セッションのページは既に `setNavbarCenter` で操作を渡している。フラグを足すと、ページごとに 2 か所を同期する必要が生まれる
- **下タブバー**: 4 つの目的地に 1 タップで届く。ハンバーガーのドロワーは 2 タップかかり、存在に気づかれにくい
- **ドロワーは「どの中身へ戻るか」**: タブは「どの画面へ行くか」で、毎日行き来する 4 つの行き先はタブに残す。ドロワーには、開く理由になる「続きから」「最近のノート」と、たまに使うカレンダー・アカウントを入れる。タブのラベルは消さない（アイコンの意味が普遍的でなく、タッチ端末ではツールチップが出ないため）
- **見出しは消さず、ヘッダーの代わりにする**: 「今日の復習」はタブの「復習」より範囲が狭いことを伝え、`h1` は読み上げの目印になる。区切り線のあるヘッダーとページの見出しを 2 段に積まず、1 行にまとめる
- **`[@media(hover:none)]:opacity-100` は残す**: ホバーが無い端末で見せる規則で、押し方の規則とは別の問い

## Consequences

- 幅の規則と入力手段の規則を使い分ける規約を `docs/design/ui-guidelines.md` に持つ
- タッチ端末でも hydration の直後までは `useCoarsePointer()` が `false` で、Enter が送信になる（直後に切り替わる）
- 画面ロック中はマイクが止まる（Wake Lock は入れない）。ソフトキーボードの表示に `visualViewport` で追従しない（`h-dvh` で足りなければ別途）
- Radix の Popover / Menu の中身は portal に出るので、`hidden md:flex` で隠した木の中にトリガーを置くと、閉じたはずの内容が表示される。1 画面に同じトリガーを 2 つ描画しない
- 外付けキーボード付きのタブレットは主ポインタが粗いままなので、Enter は送信にならず改行になる（送信はボタン）。入力手段の軸で決めた帰結として受け入れる
- セッションのヘッダーは `Navbar` が一度だけ描画する（スマホ幅でも `navbarCenter` があれば表示）。`MobileHeader` はスロットが空のときだけ出る
- ドロワーは開いたまま幅が `md` 以上になる（横向きへの回転など）と、見えなくても Radix のモーダルがスクロールとクリックを止める。このため `MobileHeader` だけは `matchMedia("(min-width: 48rem)")` の変化で閉じる（状態のリセットで、レイアウトの判定は CSS のまま）。ルートが変わったときも閉じる（戻る操作など）
