# ADR-010: 音声モードを「声で話す」対話に置き換え、「以上」で送り、読み上げをストリーミングにする

## Status

Accepted（2026-10-05）。ADR-008 の録音の開始・無音検出・送信の合図・読み上げの方式を置き換える

## ADR-008 との違い

| | 音声モード（ADR-008） | 声で話す（ADR-010） |
| --- | --- | --- |
| 開始 | トグルをオンにし、発言ごとにマイクを押す | 「声で話す」を 1 回押す。以降は手を使わない |
| 送信 | 録音を止めたら送る | 最後の発話区間の末尾が「以上」なら送る。Enter でも送れる |
| 割り込み | しない | 読み上げ中・応答中に話し始めたら黙る |
| 文字起こし | 1 回の録音を webm で 1 回 | 発話区間ごとに WAV で（`stt_method = 'segmented'`） |
| 読み上げ | mp3 を丸ごと受け取ってから再生 | PCM をストリーミングで受け取り、届いた分から再生。速度 1.0 / 1.25 / 1.5 |

## Context

ADR-008 は「録音の開始は常にユーザー操作」「無音検出は入れない」とした。使ってみると、発言ごとのマイク操作は手間で、話し始めるまでの待ちも長く、読み上げもゆっくりだった。

## Decision

- 「声で話す」の 1 回の操作で、マイクの許可・`AudioContext` の解錠・聞き取りを始める。以降は音量の VAD で発話区間に切り、区間ごとに文字起こしする
- 送信の合図は沈黙ではなく、最後の区間の末尾の「以上」。Enter でも送れる
- 読み上げ中・応答中に話し始めたら読み上げを止め、その応答の残りを読まない
  - #482 で変更: 止めるのは一時停止で、割り込みの発話の後に一定時間黙ると止めた文の頭から再開する。割り込みで発言を送ったときだけ、その応答の残りを読まない
- 読み上げは `gpt-4o-mini-tts` の PCM をストリーミングで流し、届いた分から隙間なく鳴らす
- 応答は今までどおり LangGraph が作る

## Reasons

- **沈黙で送らない**: プロテジェ効果では考えながら長く説明する。考えている間の沈黙を話し終わりと取り違える
- **区間ごとに文字起こしする**: 沈黙の間は送らないので、考えている時間に費用がかからない。webm は途中で切ると 2 つ目以降の区間にヘッダーが無いので、PCM を取って WAV で送る
- **speech-to-speech のリアルタイムモデルを採らない**: 応答を LangGraph の外で作ることになり、事前分析・深さの地図・`turn_analysis` の保存と eval の regression を迂回する。音声出力の料金も TTS より桁が大きい
- **ストリーミングの文字起こし（`gpt-live-transcribe`）は第 2 段階で比べる**: 「以上」から送信までの短縮は 1 秒程度で、応答生成と読み上げの待ちのほうが大きい。`stt_method` / `stt_latency_ms` を発言に残し、同じ人が切り替えて比べる

## Consequences

- `dialogue_messages` に `stt_method` / `stt_latency_ms` を足した（プロンプトに入れない値）
- 文字起こしの 1 日上限を回数から秒数（`DAILY_TRANSCRIPTION_SECONDS`）に変え、`transcription_usages.audio_seconds` を足した
- スピーカーで使うと、エコーキャンセルが効ききらない環境では AI 自身の声で割り込むことがある。パネルでイヤホンを推奨する
- 「以上」は誤変換されやすい。文字起こしのプロンプトで指定し、末尾にあるときだけ反応する
- 読み上げの上流が本文の途中で失敗するとサーバーは本文の転送を異常終了させ、クライアントはその文の保持を捨てて失敗の通知を出す
- グラフ・`LearningState`・eval・capture・`GRAPH_VERSION` は変えない
